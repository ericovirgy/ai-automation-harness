# Threat model

Scope: an agent or automation that can request tool calls, a human approver, and an operator who
owns the policy and the tool registry. The handler code and the Python process are trusted; a
compromised process or a malicious operator is out of scope (see Non-goals).

Each row maps a threat to the control that addresses it and to the tests that exercise it. The
test references are checked by `tests/test_docs.py`, so a renamed or deleted test breaks the build.

| Threat | Control | Tests |
| --- | --- | --- |
| **T1. Unauthorized tool invocation.** The agent calls a tool that is undeclared, or one it was never granted. | Unknown tools fail closed. `allowed_tools` is an explicit list (deny by default); `denied_tools` always wins. The executor re-evaluates policy and refuses on DENY. | `tests/test_policy.py::test_example_5_unknown_tool_is_denied_fail_closed`, `tests/test_policy.py::test_example_4_delete_file_is_denied_by_default`, `tests/test_execution.py::test_executor_refuses_denied_requests_and_never_touches_the_world` |
| **T2. Undeclared action or write through a read-only tool.** | Actions must be declared per tool. The caller's claimed side effect must equal the declaration. | **T3. Privilege escalation via scope.** The agent asks for a broader scope than the tool or policy grants. | Scopes are exact strings (no wildcards). A scope must be declared by the tool and granted to that tool by the policy, which cannot exceed `allowed_scopes`. | `tests/test_policy.py::test_excessive_scope_is_denied`, `tests/test_policy.py::test_scope_declared_by_tool_but_not_granted_by_policy_is_denied`, `tests/test_policy.py::test_policy_cannot_grant_scope_a_tool_never_declared` |
| **T4. Prompt or tool-output injection triggers an unsafe tool.** Data returned by one tool instructs the agent to call another. | The harness evaluates what is requested, not why. The injected request meets the same policy and is denied. | `tests/test_adapters.py::test_prompt_injection_in_tool_output_cannot_trigger_a_deletion` |
| **T5. Argument abuse.** Path traversal, smuggled extra arguments, recipients outside an allowlist, type confusion. | Strict per-tool argument specs, unexpected arguments rejected, glob allowlists with traversal-style values refused before matching. | `tests/test_policy.py::test_unexpected_or_invalid_arguments_are_denied`, `tests/test_policy.py::test_path_allowlist_cannot_be_bypassed`, `tests/test_policy.py::test_valid_looking_request_is_still_denied_by_allowlist` |
| **T6. Approval bypass.** Running a gated action with no approval, an expired or rejected one, a reused one, one for different arguments, or self-approval. | Approval is explicit, expiring, single use, bound to the exact arguments digest, and cannot be given by the requester. The executor consumes the approval itself. | `tests/test_approvals.py::test_nothing_is_implicitly_approved`, `tests/test_approvals.py::test_approval_is_bound_to_the_exact_arguments`, `tests/test_approvals.py::test_approved_request_can_be_consumed_exactly_once`, `tests/test_approvals.py::test_requester_cannot_approve_its_own_request`, `tests/test_harness.py::test_expired_approval_never_executes`, `tests/test_harness.py::test_high_risk_action_without_approval_never_executes` |
| **T7. Policy drift between approval and execution.** | The executor re-evaluates the current policy before running, so an approval cannot outlive a stricter policy. | `tests/test_harness.py::test_policy_change_between_submit_and_resume_is_enforced` |
| **T8. Registry bypass.** Adding a tool after startup, calling a handler directly, tampering with a declaration. | Registry is sealed when the harness is built. Specs are frozen. Handlers are not exposed publicly. The executor is the only caller. | `tests/test_harness.py::test_tools_cannot_be_added_after_the_harness_is_built`, `tests/test_harness.py::test_executor_is_the_only_path_to_a_handler`, `tests/test_registry.py::test_registry_does_not_expose_handlers_publicly`, `tests/test_registry.py::test_specs_are_immutable_after_declaration` |
| **T9. Silent capability creep in a read-only client.** A future change adds a write method. | The read-only surface is pinned, read-only handlers may not reference the write side, and every read-only tool is run for real and must leave the world digest unchanged. | `tests/test_read_only_guard.py::test_read_only_world_surface_is_pinned`, `tests/test_read_only_guard.py::test_the_pin_actually_detects_a_smuggled_write_method`, `tests/test_read_only_guard.py::test_read_only_handlers_never_reference_the_write_side` |
| **T10. Malformed or ambiguous policy.** Duplicate keys, aliases, an attempt to configure default allow, a tool both allowed and denied, scopes outside the ceiling. | Strict loader: unknown keys, duplicate keys and aliases are errors, deny-by-default is not configurable, and the harness refuses to start on any inconsistency. | `tests/test_policy.py::test_malformed_or_ambiguous_policies_fail_closed`, `tests/test_policy.py::test_yaml_pitfalls_are_rejected`, `tests/test_policy.py::test_policy_referencing_undeclared_tool_is_rejected` |
| **T11. Malformed or replayed requests.** | Requests are validated on construction. Malformed input is denied and audited, not raised. | **T12. Verification bypass: success reported without the outcome.** A tool says "done" while the state is absent. | Success is a claim. Checks read state back; only `VERIFIED` yields `COMPLETED`. | `tests/test_harness.py::test_execution_success_is_not_verification_success`, `tests/test_harness.py::test_tool_returning_success_while_expected_state_is_absent`, `tests/test_harness.py::test_silent_email_drop_is_not_verified`, `tests/test_harness.py::test_incomplete_output_is_not_verified` |
| **T13. Ambiguous state interpreted as success.** State cannot be read, evidence is missing, or no checks exist. | `UNCERTAIN` is a first-class result that never completes. | **T14. Partial execution hidden behind an error.** A tool changes state and then fails. | The state digest before and after is compared; partial effects are flagged and verification is `NOT_VERIFIED`. | `tests/test_harness.py::test_failed_execution_with_partial_effects_is_flagged` |
| **T15. Evidence tampering.** Editing, deleting or reordering audit events. | Hash chain (optionally HMAC) with contiguous sequence numbers; final event binds the evidence record digest. | `tests/test_audit.py::test_editing_an_event_breaks_the_chain`, `tests/test_audit.py::test_deleting_an_event_breaks_the_chain`, `tests/test_audit.py::test_reordering_events_breaks_the_chain`, `tests/test_audit.py::test_hmac_key_prevents_recomputing_the_chain_without_the_key`, `tests/test_harness.py::test_final_event_binds_the_evidence_record_by_digest` |
| **T16. Evidence omission.** An event without its decision or verification fields. | `AuditEvent` has no defaults; the log validates every mandatory field; the harness emits full-state snapshots. | `tests/test_audit.py::test_event_cannot_be_constructed_without_every_mandatory_field`, `tests/test_audit.py::test_log_refuses_invalid_or_empty_mandatory_values`, `tests/test_harness.py::test_every_audit_event_carries_every_mandatory_field` |
| **T17. Secret leakage into logs.** Credentials in arguments, outputs or error messages. | Key-based and pattern-based redaction before any event or evidence record is written; error messages name fields, never values. | `tests/test_redaction.py::test_sensitive_keys_are_redacted_regardless_of_value`, `tests/test_harness.py::test_secrets_in_arguments_errors_and_outputs_never_reach_audit_or_evidence`, `tests/test_requests_and_models.py::test_error_messages_never_echo_values` |
| **T18. Double spend of an approval under concurrency.** Two callers resume the same approved request at once. | `ApprovalGate.consume` is atomic (lock) and the harness serialises requests, so one approval runs one action. | `tests/test_security_review_fixes.py::test_an_approval_cannot_be_spent_twice_concurrently`, `tests/test_security_review_fixes.py::test_gate_consume_is_atomic_under_contention` |
| **T19. Verification of the wrong object.** The tool acts on, or returns, something other than what was requested, and the checks only inspect its own output. | Checks compare the result and the observed state with the *request*, and receipts must match the object they claim to evidence. | `tests/test_security_review_fixes.py::test_acting_on_the_wrong_object_is_not_verified_for_delete`, `tests/test_security_review_fixes.py::test_returning_a_different_file_than_requested_is_not_verified`, `tests/test_security_review_fixes.py::test_receipt_for_a_different_object_does_not_count_as_evidence` |
| **T20. Evidence overwrite by choosing request ids.** A caller picks ids that collide with synthetic evidence references. | Synthetic references use a prefix that client ids cannot produce; the store refuses silent overwrites; scenario ids must be unique. | `tests/test_security_review_fixes.py::test_synthetic_evidence_refs_cannot_collide_with_client_chosen_ids`, `tests/test_security_review_fixes.py::test_evidence_store_refuses_silent_overwrite` |
| **T21. Parser differentials and crashes in audit and policy input.** Duplicate JSON keys, non-canonical lines, malformed hashes, pathological YAML, special files. | Audit lines must be canonical and key-unique; malformed input is an `AuditIntegrityError` or `MalformedPolicyError`, never a crash; policy files must be regular files and are read with a bound. | `tests/test_security_review_fixes.py::test_duplicate_keys_in_an_audit_line_are_rejected`, `tests/test_security_review_fixes.py::test_non_canonical_audit_lines_are_rejected`, `tests/test_security_review_fixes.py::test_pathological_yaml_is_a_controlled_error`, `tests/test_security_review_fixes.py::test_policy_path_must_be_a_regular_file` |
| **T22. Validation bypass through type tricks.** A `str` subclass that lies about `split`, or a `ToolRequest` subclass. | Exact types are required for ids, scopes and arguments; subclasses of `ToolRequest` are re-validated. | `tests/test_security_review_fixes.py::test_str_subclasses_cannot_smuggle_past_validation`, `tests/test_security_review_fixes.py::test_a_request_subclass_is_revalidated_not_trusted` |

## Non-goals and residual risk

* **Trusted process.** Handlers run in the same process. Python offers no real isolation, so code
  that deliberately reaches into private attributes can bypass in-process controls. The invariants
  above defend against mistakes and casual misuse, not against a hostile handler.
* **Hash chain without an anchor.** Anyone who can rewrite the whole log can recompute a plain
  SHA-256 chain, and tail truncation is invisible without an externally recorded head hash. Use the
  HMAC option with a protected key and record `head_hash` elsewhere.
* **Single process.** Requests are serialised by one lock in one process. Nothing is persisted, so
  approvals and audit state do not survive a restart and cannot be shared between processes.
* **Requester identity is caller-supplied.** The "requester cannot approve" rule compares names
  case-insensitively but cannot stop an embedding system from lying about who the requester is.
* **Redaction is pattern based.** It covers common key names and token formats, not every possible
  secret. Treat it as a safety net, and do not put secrets in tool arguments.
* **Approver identity is a string.** The gate enforces "named, and not the requester". It does not
  authenticate anyone; that belongs to the system embedding the gate.
* **No timeouts or resource limits** on handlers, and no persistence of approvals or audit state.
* **Simulated tools.** Nothing here proves a real integration is safe; the verification checks of a
  real tool must be written and reviewed for that tool.
